## 2. V1.0 — required before release

### 2.1 Commit the work that already exists but isn't in git (the root-cause fix)

Every "Critical" finding in RC1 traces back to this. Covers: CI workflow, CLI entry point, the R5/R6 coverage-remediation test suite, and the Run Manifest System production code — all reviewed and tested this engagement, none of it committed. This is not a code change; it's making the repository's git history match what has actually been built and verified.

### 2.2 Add a `LICENSE` file matching the MIT claim in `pyproject.toml`

Direct legal-clarity gap (Docs Audit + RC1).

### 2.3 Declare `youtube-transcript-api` as a dependency

Code Audit Critical #1 — `collect/transcripts.py` imports a package that isn't in `pyproject.toml`; the transcripts stage is broken on any clean install. `poetry.lock` regeneration still needs to happen outside this sandbox (same Python-version blocker as R3), same as before.

### 2.4 Reconcile the version number

`pyproject.toml` (`0.1.0`) vs. `config/settings.yaml`'s `study.version` (`1.0.0`) (RC1). Bump the package version to `1.0.0` to match — this release *is* v1.0.

### 2.5 Add a `py.typed` marker

RC1 — the `"Typing :: Typed"` classifier is false without it.

### 2.6 Remove the debug prints and dead code in the YouTube provider's error handler

Code Audit Major #2-3 — unstructured `print()` calls on every transient API error, plus unreachable code that silently drops `RateLimitError` classification for non-quota 403s and leaves HTTP 429 completely unclassified. This is a correctness bug in error handling, not a feature.

### 2.7 Fix the quota-persistence failure masking a successful run as `FAILED`

Code Audit Major #7 — one-line-scope fix (wrap in the same best-effort pattern already used for manifest writes), directly undermines the just-built Run Manifest System's reliability if left as-is.

### 2.8 Broaden CLI error handling to the platform's typed exceptions

Code Audit Major #8 — currently only `FileNotFoundError` gets a clean message; every other platform exception (`FinfluencerError` and its subclasses) dumps a raw traceback. Minimal fix: catch `FinfluencerError` alongside `FileNotFoundError`.

### 2.9 Guard the raw dict-indexing in comment parsing

Code Audit Minor #10 — one unguarded `dict[...]` chain that can `KeyError` on a malformed API response and abort an entire run.

### 2.10 Give `resolve_channel()` a clear error for unsupported URL forms

Code Audit Major #9 — `/c/` and `/user/` legacy YouTube URLs currently produce a confusing mangled-handle lookup failure instead of a clear "unsupported format" message. Scope: better error message, not new resolution capability (resolving legacy custom URLs would require a different API call and is a real feature addition — deferred, §3).

### 2.11 Make sampling under-delivery visible

Code Audit Major #6 — `_month_stratified_sample()` can silently return fewer than the requested quota. Scope for v1.0: log a warning when this happens, so it's visible instead of silent. Redesigning the sampling algorithm itself is deferred (§3) — changing it would change which videos get sampled for studies already in flight, which is a bigger decision than this pass should make unilaterally.

### 2.12 Fix the broken `ARCHITECTURE_v2.1.md` doc reference

RC1 + Code Audit — points at a file that doesn't exist, sits right above `__version__`.

### 2.13 Document the checkpoint manager's single-writer assumption

Code Audit Minor #12 — one docstring addition; no locking implementation (that would be a new feature, deferred).

### 2.14 Add `.env.example`

RC1 Minor — document `ANON_SALT`, `EVDS_API_KEY`, `YT_API_KEY`.

### 2.15 Write a real `README.md`

Docs Audit — description, install steps, quick start, links to license/citation/architecture, minimal troubleshooting (seeded from the existing `README.txt` Windows-fix content), basic badges.

### 2.16 File `CHANGELOG.md`

Docs Audit — extracted from the draft already sitting in `Version_1.0_Release_Checklist.md` §3.

### 2.17 Write `CONTRIBUTING.md`

Docs Audit — minimal version: branch/PR conventions, test/coverage expectations.

### 2.18 Add a minimal `CITATION.cff`

## 3. Deferred to v1.1 (explicitly out of scope for this pass)

- **Untrack the 108 tracked `.pyc`/`__pycache__` files and 17 tracked data/checkpoint files** (RC1 Major). Real issue, but high blast radius (125 files) and it directly reverses a scope boundary the user explicitly drew during R1 ("do not expand R1 beyond untracking `.env`... future/separate scope"). Not implementing without fresh explicit sign-off.
- **Implement actual retry logic via `tenacity`** (Code Audit Major #4). The dependency is declared and the docstring claims this behavior, but building real retry semantics (which errors, how many attempts, backoff policy) is a genuine new feature requiring design and test coverage, not a bug fix.
- **Per-item exception isolation redesign** across `channels.py`/`videos.py`/`comments.py` (Code Audit Major #5). Deciding which exceptions are safe to skip-and-continue vs. fatal is a design call, not a mechanical fix.
- **Redesign the systematic sampling algorithm** to be collision-free (Code Audit Major #6, algorithmic half). See §2.11 — only the visibility fix ships now.
- **Full ADR system** (`docs/adr/` directory, index, template) (Docs Audit).
- **Data Availability Statement** (Docs Audit). Requires actual research-team policy input on what's shareable vs. restricted — not something to fabricate.
- **Fill in real `pyproject.toml` URLs and author email** (RC1). I don't have the real GitHub org URL or contact email; inventing one would be worse than leaving the current, honest placeholder. Needs the user to supply real values.
- **`mkdocs`/`pre-commit` config or removal** (RC1 Minor) — low priority, either build out the tooling or drop the unused dependencies; not blocking.
- **FAQ** (Docs Audit) — explicitly recommended to grow organically post-release rather than be drafted speculatively.
- **Remove `config/analysts_backup.yaml` / stray `manifest.txt`** (RC1 Cosmetic) — trivial, low value, not worth commit noise in this pass.
- **Legacy Poetry `[tool.poetry.*]` → PEP 621 `[project]` migration** (RC1 Major) — real but structural; risk of breaking the build without a working `poetry install` environment to test against in this sandbox.
- **Building/verifying a wheel or sdist** — blocked by this sandbox's Python 3.10.12 vs. the project's `>=3.11` floor; first real verification happens once CI actually runs (§2.1).
- **Cutting the `v1.0.0` git tag** — a release action, not a code fix; left for the user to do explicitly once these commits are reviewed, per the existing `Version_1.0_Release_Checklist.md` process.

## 5. Commit plan

Implementation proceeds as a sequence of small commits, each scoped to one logical change, in roughly this order: (1) commit pre-existing reviewed-and-tested work (CI, CLI, tests, Run Manifest System) exactly as it stands — no new edits mixed in; (2) new v1.0 fixes from §2, each as its own commit. Pre-existing uncommitted changes in files I also need to edit (e.g. `pyproject.toml` already has an uncommitted `yfinance`/market-extras addition) are committed first, as-is, before any new edit is layered on top — so no commit mixes someone else's unreviewed-by-me change with mine.

Explicitly **not** touched: `config/analysts.yaml`, `config/settings.yaml`, `core/contracts.py`, `core/config.py`, `providers/market/__init__.py`, `coverage.xml`, `poetry.lock`, any `data/`/`checkpoints/`/`cache/` contents, and the large set of untracked manuscript/report/analysis files at the repository root. Their existing diffs are outside this remediation's scope and their provenance isn't something I can respons­ibly commit on the basis of this audit alone.
