# T-027 Migration Risk Checklist — PDF Report Rendering

Scope: genuinely new implementation (no existing tested code wrapped) — render a `finalized`
`Report`'s cited `InterpretationRecord`s into a PDF file, backed by a new `Export` (T-024,
previously unused) Domain record.

## Reuse boundary

- [x] `reporting/master_table.py`, `reporting/orchestrator.py`, and every other Sprint 1/2.1
      reporting module were re-checked for a PDF/HTML rendering path — none exists
      (`manuscript_figures.py`/`manuscript_tables.py` produce academic publication tables/figures,
      not an in-product `Report` render). Confirmed by direct inspection, not assumed from the
      Roadmap's own "[New for rendering]" tag alone.
- [x] No modification to any existing `reporting/` module. T-027 adds new files only.
- [x] `jinja2` (`pyproject.toml`, "Templating (report / Publication Engine)") is **not** used —
      zero import in this task. Deliberately deferred to a future layout-polish fast-follow (see
      Known technical debt in the Context Pack) rather than pulled in for a templating need this
      task's minimal scope doesn't actually have yet.

## Domain Model boundary

- [x] `Export`/`ExportFormat` (T-024) are reused **unchanged** — this is the first task to
      actually construct one. No new `ExportFormat` member added (`WORD` stays out per T-024's
      own TODO).
- [x] `Report.finalize()`/`Report.citation_ids` (T-024) are reused unchanged, called and read
      only, never re-implemented.
- [x] `InterpretationRecord` (T-024) is read-only here — `id`, `analysis_run_id`, `kind`,
      `selector`, `content` are read to build PDF content; nothing is mutated (it has no mutating
      methods regardless).
- [x] One new Domain repository interface, `IExportRepository` (`add`,
      `get_by_report_version_and_format`) — exactly the surface `GenerateExportOrchestrator`
      needs, same minimal-surface discipline as every prior repository addition.
- [x] One new Domain port, `IPdfRenderer` (`domain/reporting_engine.py`), mirroring
      `IResultSnapshotReader`/`ITableExporter`'s existing shape exactly.

## Layering (IG-001)

- [x] New Infrastructure adapter (`infrastructure/reporting/pdf_renderer_adapter.py`) imports
      only `reportlab.*`, `pathlib` — no Presentation/API import, no repository import
      (ast-verified in tests).
- [x] New Application orchestrators (`generate_export.py`, `finalize_report.py`) import no
      `reportlab`, no `finfluencer.infrastructure.*` — same discipline as every prior
      orchestrator (ast-verified in tests).

## Business rules (BKG-001)

- [x] "`Export` may only be generated from a `FINALIZED` `Report`" (§10.1 line 597/608) is
      enforced in `GenerateExportOrchestrator` (Application), never in the Infrastructure
      renderer.
- [x] `FinalizeReport`'s idempotency ("finalizing twice is a no-op", §11.2 line 727) is enforced
      in `FinalizeReportOrchestrator` (Application) by checking status *before* calling
      `Report.finalize()` — the Domain method's own terminal-state guard
      (`DomainInvariantViolation` on a second call) is left unchanged, exactly as a guard should
      behave; idempotency is an orchestration concern layered on top of it, not a relaxation of
      it.
- [x] `GenerateExport`'s idempotency ("re-request returns the existing Export, no duplicate
      render", §11.2 line 727) is enforced via the natural `(report_id, report_version, format)`
      key through `IExportRepository.get_by_report_version_and_format`, in Application — no
      separate caller-supplied idempotency token is introduced (flagged design note, Readiness
      Review Q8).

## New external dependency

- [x] `reportlab` added to `pyproject.toml` as a runtime dependency — no PDF rendering library
      was previously declared anywhere in the project; ADR-0001 does not name one. Recorded as
      **ADR-0003** (new, dated entry) per Playbook Part E's ADR policy ("any implementation-level
      decision with lasting consequence").
- [x] `pypdf` added to `pyproject.toml` as a **dev-only** dependency — used exclusively by the
      automated content-match test to read rendered PDF text back out; never imported by
      production code (ast-verified).
- [x] `poetry.lock` regeneration remains environment-blocked in this sandbox — same root cause
      already recorded for T-002/T-003 (no obtainable `poetry lock` run here). Both new
      dependencies are already importable in this sandbox's ambient Python environment (verified
      directly), so tests run and pass here, but the lock file itself is not regenerated by this
      task. Flagged, not silently glossed over.

## Idempotency / side effects

- [x] `PdfRendererAdapter.render()` is a pure write-one-file operation — no repository or network
      side effect inside Infrastructure.
- [x] `GenerateExportOrchestrator` calls the renderer at most once per distinct
      `(report_id, report_version, format)` — a repeat call returns the previously-persisted
      `Export` without re-invoking `IPdfRenderer.render()`.

## Cross-project isolation

- [x] `GenerateExportOrchestrator`/`FinalizeReportOrchestrator` resolve `Report` through
      `IReportRepository.get_by_id(project_id, report_id)` — the same project-scoped lookup every
      prior orchestrator uses; a citation from another project's `Report` cannot be exported.

## What this checklist deliberately does not cover

- Publication-quality PDF layout (typography, headers/footers, per-`AnalysisType` table
  rendering of snapshot content) — BACKLOG.md's own Internal Review names this as the fast-follow
  half of T-027 if the task ran long; deferred here as a matter of deliberate MVP scope, not
  because it ran long. Recorded as Known technical debt in the Context Pack.
- Real-scale PDF performance (large snapshot content, many citations) — not exercised in this
  sandbox, same class of deferred verification as every prior adapter task.
- Async job execution for `GenerateExport` — §11.2 line 728 names it architecturally
  asynchronous; implemented synchronously here, the same MVP-stage simplification already
  established for `StartAnalysisRunOrchestrator` (§11.2 line 702, also architecturally async).
